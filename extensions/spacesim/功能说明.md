# spacesim 功能说明

本文档是 [README.md](README.md) 的中文版，覆盖：为什么有这个包、有什么、
怎么用、有哪些约束。代码结构和约束完全相同。

## 一、做什么

在 Hypatia（Kassing 等，IMC 2020）之上做 **LLM-on-satellite** 仿真：
用户在浏览器界面里配置 LEO 星座、地面 GS、LLM 请求工作负载和计算成本模型，
点 Run 就跑一次完整的 satgenpy 状态生成 + ns-3 仿真 + 结果可视化。

仿真器把以下层都封装好了：

| 层 | 职责 | 主要入口 |
|---|---|---|
| `topology/` | Walker-Star + Grid 拓扑生成（调 satgenpy）、卫星角色分配、为 SAT 目的地补 fstate 路由、距离-最远 dst SAT 选择 | `generate_topology`、`roles.assign_by_plane`、`fstate_augment.compute_augment_rows` |
| `workload/` | LLM 请求 schedule 生成（15 列 CSV）、ns-3 配置渲染、ns-3 C++ 模块源码 + 安装脚本 | `generate_schedule`、`write_ns3_config`、`install_ns3_module.sh` |
| `runner/` | 用线程 + subprocess 启 ns-3，行缓冲实时 stdout，超时保护 | `HypatiaRunner` |
| `analysis/` | 解析 3 份 CSV log → 每请求生命周期 DataFrame | `build_lifecycle_df`、`summarise`、`stage_means_ms` |
| `viz/` | Plotly 3D 地球、延迟 CDF / 直方图、各阶段堆叠条图 | `make_globe_figure`、`plot_cdf`、`plot_stage_breakdown` |
| `config/` | 全部 dataclass + JSON 往返 + topology hash | `ExperimentConfig` |
| `dashboard/` | Streamlit 主 UI | `app.py` |
| `scenarios/` | 预置经典实验 | `scenarios/*/run.sh` |
| `tests/` | 57 个 pytest 用例 | `./run_tests.sh` |

## 二、快速开始

```bash
# 一键启动 dashboard:
cd /home/mark/spacesim/hypatia/extensions/spacesim
./start.sh                       # http://localhost:8501

# 或者跑全部测试:
./run_tests.sh                   # 57 用例 ~5s

# 或者纯看历史 cached 结果, 啥也不跑:
ls runs/                         # 之前跑过的 run dir, 比如 tokyo_to_sat894/ 或 run_<timestamp>_*/
```

Dashboard 侧边栏的 **"Inspect a previous run"** 下拉自动发现 `runs/`
和 `scenarios/*/run/` 下所有带 Phase-C log（`llm_gather_node*.csv`）的目录，
不跑仿真也能看历史结果。

## 四、两条不能破坏的契约

1. **`satellite_roles.txt`**——run dir 里的文件，格式
   `<sat_id>,<C|T>` 每行一颗卫星。ns-3 的 C++ 补丁
   （`topology-satellite-network.cc`）在仿真启动时读它，把 type=C 的
   卫星加进 `m_endpoints`，schedule reader 才会接受 SAT 当端点。
   `topology/roles.py` 写出这个格式。

2. **Phase-C log schema**——ns-3 `llm-workload` 模块产出的三族 CSV：
   - `llm_gather_node<sat>.csv` （**关键字段** `t_emit_ns` 在这里）
   - `llm_compute_node<sat>.csv`
   - `llm_response_node<gs>.csv` （单 req 多包，多行）

   `analysis/lifecycle.py` 的 `build_lifecycle_df` 把三个 JOIN 起来，
   join key 策略写在该文件的 docstring 里——`req_id` 是 per-GS 的，
   不全局唯一，朴素 merge 会笛卡尔爆炸。

## 五、Pipeline 一图流

```
ExperimentConfig (来自侧边栏 / JSON)
        │
        ▼
topology.build.generate_topology()
   ├── satgen.generate_tles_from_scratch_manual()
   ├── satgen.generate_plus_grid_isls()
   ├── satgen.help_dynamic_state()              ← 最慢
   ├── roles.assign_by_plane()                  → satellite_roles.txt
   └── fstate_augment.py (subprocess)           → 加 SAT-dst 路由
        │ (按 topology_hash 缓存到 cache/<hash>/)
        ▼
workload.schedule.generate_schedule()           → llm_workload_schedule.csv
workload.ns3_config.write_ns3_config()           → config_ns3.properties
        │
        ▼
runner.hypatia.HypatiaRunner.start/finalise()
   └── ./waf --run "main_satnet --run_dir=…"
        │
        ▼ logs_ns3/llm_*_node*.csv
analysis.lifecycle.build_lifecycle_df()         → 每请求 DataFrame
        │
        ▼
viz.{globe, latency, breakdown}                  → Plotly 图
        │
        ▼ Streamlit dashboard
```

## 六、五条已知限制

| # | 限制 | 说明 |
|---|---|---|
| 1 | `max_isl_length_m` 设为轨道直径 ×0.99 | Walker-Star phase_diff 让稀疏星座 cross-plane ISL 比赤道-相邻几何估计大；为了兼容所有 +Grid 边，干脆用轨道直径上限。代价：ISL 不再强制不"贴着"大气层。详情见 `topology/build.py::_max_isl_length_m` |
| 2 | satgenpy 要求 ≥ 10 个 fstate timestep | 上游 `generate_dynamic_state.py` 在 progress logger 里 `floor(N/10)`，N<10 时除以零。`topology/build.py` 拒绝跑不够 timestep 的 config，抛清晰错误。我们不补 satgenpy |
| 3 | fstate 不允许注释行 | ns-3 parser `split_string(",", 5)` 期望精确 5 字段，`#`-开头行直接 SIGIOT。`fstate_augment.py` 一行注释都不写，用 sidecar `.phase_a_augment.json` 记录已 augment 的 `(dst, t)` |
| 4 | `req_id` 是 per-source-GS 不全局唯一 | 多 GS 时不同源同 `req_id` 会让 inner-join 笛卡尔爆炸。`build_lifecycle_df` 用 `(req_id, L_in, L_out)` 接 gather→compute；用 `(req_id, src_node_id==gs_node_id)` 接 → response |
| 5 | 3D globe 不是 SGP-4 | dashboard 的 globe 用解析圆轨道画 t=0 卫星位置；仿真本身用 SGP-4。视觉上 t=0 一致，长时间会偏 |

外加一条**版本性限制**：schema 支持多 shell 列表，但 `generate_topology`
只 materialise `config.shells[0]`（多余的 shell 会打印 warning 然后忽略）。

## 七、历史

这个包是三个前作的合并：

- **Phase A**——让 compute satellite 成为合法流量端点：C++ patch
  + `satellite_roles.txt` 契约 + `fstate_augment.py`
- **Phase B**——ns-3 `llm-workload` C++ 模块（请求 + sink，无回程）
- **Phase C**——完整 LLM 请求生命周期：gather + compute + response

原始工作日志、result.md、各 phase README 都原封不动存档在
[`docs/history/`](docs/history/)。

Streamlit dashboard 是在三个 phase 之上建的。合并完成后所有功能都
在这一个包里，phase_a/b/c 的命名彻底退场。
